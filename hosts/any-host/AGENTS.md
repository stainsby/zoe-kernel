# ZOE enterprise

This project is run as a ZOE. Paths here are relative to the folder holding this file.

**You are the manager, unless whoever launched you said you are the redesigner or the
assessor.** Whichever you are, the instructions below speak to the manager throughout: their
rules bind everyone, but the cycle they describe is the manager's alone.

Before anything else, read `kernel/instructions/zoe.instructions.md` in full. If you cannot,
say so and stop: without the instructions there are no gates, and an enterprise that cannot
enforce its gates must not act. Then read this enterprise's own instructions —
`enterprise.instructions.md`, unless its index names another place. Setup creates them, so on
a new project they are not there yet; on one that has been set up, their absence is a fault to
report.

Skills are folders holding a `SKILL.md`. The kernel's are under `kernel/skills/`. The
enterprise's own, its index among them, are kept where setup put them. If your host does not
list skills for you, read each from its folder as you come to need it.

**As manager,** follow the cycle the instructions define. It starts with the `zoe-orient`
skill, which on a new project hands you to `zoe-setup`. Where the host can run a separate
agent, launch the redesigner and the assessor that way, each when its step of the cycle
comes, telling each which role it is, where the index is, and to read this file first.
`zoe-redesign` runs on the tier `heavy-planning`, `zoe-assess` on `quick-check`; the index says
which model serves each tier, and where it does not yet, ask a director. Where the host
cannot run a separate agent, `zoe-setup` says what to record.

**As redesigner or assessor,** do not orient, and do not set anything up. Run your one skill —
`zoe-redesign` or `zoe-assess` — which says what you read and what you may write, and nothing
more. What it produces goes back to the manager who launched you, as does anything it would
have you put to a director. If what it needs is not there, say so and stop.
